## 6. 隔离恢复演练清单

以下是下一任务的验收流程，尚未在本轮执行，也不是在正式安装上覆盖文件的指令。

1. 明确备份时间、程序版本和数据库版本；选择对应备份。正常停止产生备份的应用实例，等待在途任务完成，再取得一致副本。
2. 校验 `manifest.json` 中的数据库／完整知识目录哈希；升级备份另查 `configuration-manifest.json` 和 `configuration/`。底层 `backup_storage` 本身只备份数据库与知识目录，不能假定任何备份都含配置或程序。
3. 在项目 `.cache` 下创建独立恢复目录，放入匹配的干净程序、SQLite、完整知识目录（含隐藏身份标记）和该时点配置；不与现有数据库、知识目录或 Qdrant owner 并行共用索引。
4. 首次恢复进程显式关闭 AI/RAG，检查路径和外部启动配置；不因旧配置开启而意外重发模型调用。恢复更早的备份可能没有后加的 `local-rag-startup.json`，应按备份时点理解。
5. 核对数据库版本、`integrity_check`、`foreign_key_check`、Source／Knowledge／关联／模板／草稿／任务数据及完整文件哈希。已中断任务保持显式继续，不自动重新生成。
6. 检查 vault 标记、同步基线、路径及冲突状态；确认正常扫描不会把读取失败或错配解释为批量删除，不新建标记来掩盖问题。
7. 使用独立 Qdrant 卷验证快照恢复，或验证当前兼容向量缓存的重建路线，两者分别记录。当前没有统一 Qdrant 快照管理命令，应在后续任务中核对固定版本支持的操作并演练；本轮不发明未经执行的命令。SQLite 丢失时，单有 Qdrant 卷不能恢复完整知识库。
8. 取得期望检索结果后正常退出，确认端口／实例释放；仅清理属于演练的资源，保留报告和可用备份。恢复正式安装须再单独执行停机与回退计划。

配置和备份可能含密钥、全文及模型结果，不能当作公开诊断附件。当前没有备份加密或安全销毁功能；需要更强本机保护时应另行约定需求。

## 8. 运行和清理边界

- **单活存储：** 一个 SQLite＋vault 由一个工作进程维护。`RLock`、文本生成额度和后台工作器都在进程内；使用 `--workers 1`。桌面互斥按目录及 Windows 会话工作，不是跨会话／跨设备的数据库协调器。复制完整库后，若仍共享同一 Qdrant owner，也不要并行运行。
- **本机使用：** API 和服务继续限制回环地址。无登录／多用户隔离，设置令牌只是部分接口的保护；局域网或公网部署需要单独设计，不能只改监听地址。
- **真实运行依赖：** `.cache/ollama/models/` 是模型权重；`.cache/ollama/service.json` 和日志是服务运行资料，不能随构建缓存一起清除。
- **业务数据：** `data/`、`knowledge/`、个人配置、便携目录和 Docker Qdrant 卷分别确认；软删除／任务快照不是已从磁盘安全销毁。
- **可规划归档的产物：** 历史构建、验收截图／浏览器、旧备份、旧发行 ZIP；先识别用途、占用与保留要求，再实施清理，本轮不删除。
